# `paper-deep-summary` 标准 8 段式结构与写作规范参考

本文档提炼自标杆案例（FIMA-Q 论文总结与改进方案（示例案例）），用于在撰写任意学术论文深度总结时保持统一的结构深度、表格规范与文风标准。

---

## 一、8 大模块写作要点清单

### 0. 常用符号与缩写说明（强制包含）
按用途分 3–4 张紧凑小表（避免把几十个符号堆进一张大表）：
1. **网络模块与核心变量符号**（输入、输出、扰动/特征、维度记号等）
2. **概率分布、损失与二阶/关键指标符号**（任务损失、代理损失、梯度、矩阵算子等）
3. **方法特有超参数与中间矩阵符号**（如采样步长、秩上限、加权系数、迭代数等）
4. **领域与评测缩写**（如任务指标、设置缩写、对比表头标记等）

### 1. 一、论文主要内容
- **1.1 研究背景与技术定位**：
  - 用 **Mermaid 横向流程图（`flowchart LR`）** 画出本文所处的单线演进树（祖先 $\rightarrow$ 靶子/框架 $\rightarrow$ 本文）。
  - 明确区分 **“继承与保留的组件”** 与 **“核心改进的位置”**，避免把沿用组件误写成本文创新。
- **1.2 方法整体流程**：
  - 按输入、初始化、核心循环/计算步骤、参数更新与输出，分步拆解原文 Algorithm / 框架图。

### 2. 二、核心思想
- **技术路线对比**：交待该领域常见技术路线（如“改表示”vs“改目标”），说明本文选路依据。
- **核心痛点/偏差剖析**：配 **Mermaid 流程图** 拆解前作方法做了哪些近似或存在什么局限，指出哪一步是本文真正的切入点。
- **核心理论与递进方法表**：列出核心公式（保留原文公式编号），并用表格对比从基础版到最终版的方法演进（形式、保留的信息、复杂度）。

### 3. 三、主要贡献
- 按 **理论层面 / 方法层面 / 评测层面** 三条独立证据链展开，每条贡献必须挂钩原文具体定理、公式与关键实验提升数字（如平均超越次优 X%，超越基线 Y%）。

### 4. 四、论文所做的假设
- 使用标准 4 列表格：`序号 | 假设内容 | 出现位置 | 作用与意义`。
- 客观区分 **显式理论假设**（如正则条件、分布匹配、独立性假设）与 **隐式工程/实验前提**（如校准集代表性、下游任务代理输出头等）。
- **语气要求**：把假设写成“理论与方法成立的自然前提”，不对其做脱离原文语境的苛刻否定。

### 5. 五、方法适用边界与局限
- 严格基于**论文正文、附录与汇报材料已有内容**，以“权衡（Trade-offs）与当前实证范围”的建设性口吻陈述：
  1. 不同设置/区间下的边际收益变化（例如高精度区间与专用方法的各自擅长处）；
  2. 精度提升与计算/时间成本之间的折中（引用正文实测耗时倍数）；
  3. 跨任务迁移时的工程简化范围（如仅重建骨干、头部分支纯校准）；
  4. 当前实证尚未覆盖的位宽/模型家族/超参固定情况。

### 6. 六、实验设置与实验结果证明的结论
- **6.1 实验设置**：用结构化表格汇总数据集、模型家族、校准/训练协议、硬件平台、超参数配置、工程适配策略与对比基线分类。
- **6.2 实验结果与所证明的结论**：
  - 完整保留主实验表、跨任务表、关键消融表（方法组件消融 + 超参/效率消融）的实际数值；
  - 每张表后紧跟 **“所证明的结论”**，把数字变化直接映射到前文的理论假设与贡献点（例如：“某基线劣于一阶基线直接证明了 C1；某两项合并后同时最优证明了互补性”）。

### 7. 七、未来展望与可结合的改进方向
- 提出的每个改进方向都**必须有论文正文/边界中的明确切入线索**（不能天马行空硬凑），固定采用五段式写法，讲透“从哪来、借谁的、改哪里、想要啥结果”：
  1. **切入依据**：引用本文某节/某表/某边界的明确现象；
  2. **主要思想**：一句话概括该改进方向的核心思路；
  3. **沿用哪篇论文的什么机制**：明确列出复用的相关论文（如前驱工作、正交组件或同赛道工作）及具体机制/公式；
  4. **改进了什么地方**：给出具体改动与新增模块/公式或流程改法；
  5. **渴望得到的结果（对论文结论的提升）**：明确说明预期改善的指标/现象，以及如何把原论文某条有限结论推向更强、更全面。

## 二、Obsidian `==高亮==` 标尺规范

- **高亮原则**：宁缺毋滥、精准聚焦。一篇 250–350 行的总结文档建议控制在 **20–40 处**关键高亮，让读者扫一眼就能抓住全文主线。
- **推荐高亮的对象**：
  - 核心方法名、核心机制词（如 `==标准均匀量化器==`、`==渐进式增秩==`）；
  - 核心理论发现（如 `==FIM 与 KL 散度的一阶梯度呈线性正比关系，而非梯度的平方==`）；
  - 关键量化数字与对比结果（如 `==5.31%==`、`==8.74%==`、`==480 GPU 分钟==`）；
  - 前提假设核心短语、改进方向的核心标题与目标结论。
- **绝对禁止高亮的位置**：
  1. 禁止把 `==` 放进 `$...$` 或 `$$...$$` 数学公式内部（会导致 KaTeX 渲染失败）；如需高亮含公式的短语，把 `==` 放在整句中文外部或只高亮文字部分；
  2. 禁止在 ```` ```mermaid ```` 或普通代码块内部使用 `==`；
  3. 禁止在数据表格的纯数字单元格里滥用 `==`（数据表格用 Markdown 粗体 `**数字**` 标出最优即可）。
